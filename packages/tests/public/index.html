lean-in-wasm (debug harness)

← back to the Lean IDE (this page is the lower-level WASM harness for experimenting; the real app is at /)

State: booting   — reload with a different URL query to change what's run.

What works: metadata commands like --version, --help, --print-libdir. The Emscripten runtime boots, SharedArrayBuffer + pthread workers spin up, and 86 MiB of Init oleans can be seeded into MEMFS in ~1.5s.

What does NOT work: compiling a .lean file hangs. Lean starts elaboration, then the browser context dies silently. This is an architectural limit of the v4.15.0 CLI WASM binary; shims get past the Node-only assertion but can't fix elaboration-path incompatibilities. A real in-browser Lean compile needs upstream work (a browser-oriented entry point, or a thread-model fix).
